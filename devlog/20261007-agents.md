Anselm, after reading WorkOS's auth.md (workos.com/auth-md, an open protocol for agents to register
for services on behalf of users): its pitch notices that agents need auth of their own, and "a pile

formal way for agents to declare their perms, limits"; home page: the internet is moving to
decentralized trust, "we" become our own will plus the powers we delegate to agents; "make sure the

"there's something really special about attest - that you can sign in with passkeys".

## Answer to "a formal way to declare an agent's bounds"

Read 2026-10-07: AT Protocol's permission spec (atproto.com/specs/permission: `repo:<collection>`
with optional `action=create|update|delete`, permission sets as lexicons), OAuth Rich Authorization
Requests (RFC 9396, structured `authorization_details`), UCAN v1.0 (github.com/ucan-wg/spec:
key-to-key capabilities, attenuated along a chain, DAG-CBOR envelope). Chosen: atproto permission
strings for what an agent may write (the ecosystem's own vocabulary, already used in our OAuth
scope), plus attest's own `limits.perDay`, `from`/`until`, `name`, `purpose`. The whole permission
is signed by the passkey and public, so a third party reads the bounds from it. It is a one-step
UCAN-like capability with no further delegation; adopting UCAN's encoding is possible later.

On passkeys: AT Protocol leaves sign-in to each hosting server; the reference PDS signs in with a
password and lists passkeys as planned (bluesky-social/pds issue #181, the network account
management post). Public copy says that, not "AT Protocol cannot".

## Built

- `{v:1, type:"agent", root, agent, agentKey, name, purpose, permissions, limits:{perDay}, from,
  until}`; `checkAgentDelegation` (identity.mjs); max 90 days; perDay 1 to 1000; collections limited
  to vote, comment, statement, vouch, claim, bookmark.
- Hand-off (`server/agents.mjs`), auth.md's user-claimed shape: `POST /agent/request` → code, link,
  token; the person opens `/agents/approve?code=`, signed in on attest, may narrow permissions,
  limit and days, signs with the passkey (`agent.start`/`agent.finish` over the socket); the agent
  polls `GET /agent/poll/:token`. Pending requests: memory, 15 minutes, unpublished.
- Stored in the delegations table (origin `"agent"`), logged at once as type `"agent"`, public at
  `GET /agent/:id` (HTML page or JSON). `/by` lists `agents`; sign-in delegations exclude them.
- Writes: `POST /agent/attest`, `/agent/retract`, plain HTTP (agents are programs; Anselm's
  socket preference holds for browsers). `liveDelegation` normalises both kinds; `agentMay` checks
  permission and the 24-hour count; agents cannot make admin or owner requests.
- Tightened: a site sign-in now needs its origin on every request (before, a request with no
  Origin header skipped the check); the agent endpoints refuse anything but agent permissions.
- Attribution: comments carry `via` and `del`; the widget shows "via <name>"; /me has an Agents
  section with revoke; profiles list live agents; `public/agents.html` serves approval and the
  public view.
- Client: `packages/orbital-attest/agent.mjs` (createKey, requestAccess, waitForApproval, agent),
  `agent-cli.mjs` (request, attest, retract, status; key in ~/.config/attest-agent/). Record shaping
  moved into `verify.mjs` (`shapeRecord`, `parsePermission`, `permits`) so browser and agents agree.
- `/auth.md` for agents: auth.md's idea, honestly not its OAuth shape (no PRM, no token).
- `scripts/e2e-agent.mjs`: 20 checks, all pass locally (request, refusal of foreign permissions,
  approval narrowed, public permission, writes within, refusal outside, daily limit, retract, a
  site sign-in refused on the agent endpoint, revoke, refused after). Main, cross and admin tests
  unchanged.
