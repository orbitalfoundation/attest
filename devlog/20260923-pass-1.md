## What was decided while building

- **Passkeys are the root key**, not a server-hosted key. Anselm moved
  matchmaker to passkeys this morning ("user-owned public keys"), so
  attest matches: the passkey's P-256 public key becomes a `did:key`.
  We hold a handle and a public key, nothing else. No email, no
  password, no recovery yet (custody is milestone 7).
- **Delegated device keys.** WebAuthn is origin-bound and prompts on
  every signature, which would mean Face ID per upvote. So on sign-in
  the passkey signs one 30-day *delegation* to a device key that the
  consuming site's page generates in its own IndexedDB (WebCrypto,
  non-extractable). Upvotes are then signed locally, silently. The
  delegation carries the device's public key and the site origin, so a
  delegation for one site cannot act on another. This is Farcaster's
  per-app signer under one root, and it is Friedman and Resnick's
  "arena" in code. Sign-in is the act of signing the delegation, so a
  returning user gets one prompt; a new user gets two (create passkey,
  then sign the delegation).
- **Standalone, not a PDS, for pass 1.** The brief said spike both.
  Building on a self-hosted PDS would have meant PLC registration,
  SMTP, and debugging atproto OAuth in a browser client before Anselm
  could click anything. Records keep atproto-compatible shapes
  (subject, kind, timestamp, signature, negation as retraction) so a
  PDS can come later. Storage is `node:sqlite`, one file, WAL, no
  native module, because the log wants to be a single mirrorable file
  and the VM should run nothing but Node.
- **Reads are HTTP, writes and sign-in are socket.io.** The house rule
  is socket.io; the exception it allows (static, cacheable) is exactly
  what `/read`, `/by`, `/record`, `/log` are for: a CDN and a
  retrieval agent want plain GETs. Counts push to subscribed sockets.
- **Browsers revalidate, CDNs cache.** `max-age=0, s-maxage=10`. The
  first e2e run failed twice on a stale browser cache; that was the fix.

## Module map

```
shared/did.mjs        did:key, canonical JSON, sha256 ids, ES256 sign/verify, target grammar (browser + Node)
server/store.mjs      the only SQLite access: accounts, credentials, log, delegations, records

server/passkeys.mjs   @simplewebauthn wrapper; ES256 only
server/records.mjs    acceptDelegation, acceptRecord (verification chain), read, by; emits counts
server/socket.mjs     handler map: passkey.register.*, lookup, delegate.*, attest, subscribe, whois, read
server/http.mjs       /read /by /record /log /stats, /lib/did.js, static pages
server/ratelimit.mjs  token buckets per IP and per DID
server/index.mjs      wiring
public/attest-core.js device key, session, socket requests, makeRecord, signIn (popup or same-origin)
public/attest.js      the embed widget: [data-attest] → upvote + count, optional comments, live

public/{index,about,demo,me}.html, style.css, menu.js

scripts/e2e-cross.mjs a page on another origin embedding the widget; popup sign-in
deploy/{provision,deploy}.sh
```

## The record, concretely

```
record     {v:1, type:"record", kind, by:<root did>, target, at, body?, ref?}
envelope   {record, del:<delegation id>, sig:<ES256 by device key over canonical(record)>}
delegation {v:1, type:"delegation", root, device, devKey:{x,y}, origin, from, until}
           + credentialId + the WebAuthn assertion whose challenge = sha256(canonical(delegation))
id         sha256(canonical(record)) as hex
```

Verification needs the log and the root's public key (published at
`/by/<did>`), nothing else. The e2e test does exactly that from Node
against the staged service.

## Verified

- Same-origin end-to-end, 16 checks, passes locally and against
  https://attest.exe.xyz: register, delegate, upvote, comment, reload
  keeps state, retract, second target, sign out and in, tampered record
  refused, offline verification of a record from the log.
- Screenshots of index, about, demo, login, me at phone width in light
  and dark, looked at. Code block wrapping fixed after the look.
- Cross-origin, 10 checks, passes locally: a page on a second origin embeds the widget, its own device key is delegated to by a passkey on the service origin, it signs an upvote and a comment from its origin, and the same validly signed record is refused when submitted from any other origin. Headless Chrome stalls on `window.open` under CDP, so the popup and its postMessage hand-off are exercised by the test only indirectly (the test does by hand what the popup does); the real popup needs a human on the desk.
- Staging database wiped after the test runs so Anselm starts clean.

## Not done, on purpose

Vouch and statement kinds are accepted by the server but no UI makes
them. No key export, no second passkey, no recovery. No mirror. The
`/read` privacy note stands: a first-party site's reads are as private
as its own logs. No desk integration yet (milestone 3, on his go).
