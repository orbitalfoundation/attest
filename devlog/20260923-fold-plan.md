# 2026-09-23 — decision: fold into AT Protocol; the sprint

Point-in-time. Anselm: "It seems fine to me if we have an inline
signature. I like using passkeys… I feel like we have to fold in. We
may have to sprint to a more compatible more complete feature set
before any adoption." Decision taken. This entry is the plan.

## Invariants (his)

- Passkey sign-up and sign-in, no password the person ever sees.
- Every record carries the person's own inline signature (device key
  delegated from the passkey), verifiable with the key alone.
- Ordinary sites and his other projects get sign-in and attestations
  from one service with one script tag.
- Public by construction; root-as-parameter scoring; burnable identity.

## Shape after the fold

```
passkey ──delegates──▶ device key ──signs inline──▶ record ──▶ user's atproto repo (our PDS, or a linked one)
                                                        │
                                   relay / firehose ────┴──▶ attest index (AppView): /read /by /site, scores from a root
```

- **Identity**: `did:plc` account on our PDS, created at passkey
  sign-up with a server-side secret the person never sees; handle
  `<name>.attest.monster`. A person with a Bluesky handle links it via
  the existing `bsky:` proof of control plus atproto OAuth for write
  access; records then go to their own repo.
- **Records**: `app.certified.*` shapes where they fit (follow, badge
  award, evaluation, signature proof), one lexicon of ours,
  `monster.attest.*`, for URL, DOI and hash subjects (vote, comment,
  claim, statement), each with badge.blue-style `signatures` carrying
  the device key's inline signature.
- **Index**: attest subscribes to its PDS's repo stream (and later the
  relay firehose) and rebuilds what `/read`, `/by`, `/site` serve.
  The SQLite log becomes derived state; `/log` becomes a pointer to
  the repos.
- **Scoring**: unchanged design, now over records from repos, plus
  read-in of `sh.tangled.graph.vouch`, `sh.tangled.graph.follow` and
  `app.bsky.graph.follow` as weighted edge types.
- **Widget and package**: same API; `configure({server})` unchanged.

## Sprint, in order

0. **Spike (this session).** Self-hosted PDS on the attest VM behind
   the same origin; wildcard handle hostnames through exe.dev and
   Cloudflare; create an account by API; write a record with an inline
   signature; see it on the firehose. Go/no-go on hosting.
1. **Lexicons.** `monster.attest.{vote,comment,claim,statement}` with
   `subject: uri`; validate with the atproto lexicon tooling; publish
   in the repo.
2. **Sign-up → PDS account**; delegation → inline signature; writes go
   to the repo via the PDS API instead of our table.
3. **Index from the repo stream**; reads unchanged for consumers;
   `/log` deprecated.
4. **Link an external account** (OAuth) and write to it instead.
5. **Read-in** Tangled and Bluesky graphs; **scoring** as before,
   published as a labeler.
6. **Docs, About, technical** rewritten for the new shape; catalogue
   note that attest is an application on atproto, not a fabric.
7. **Adoption**: the desk, then matchmaker.

## Stops

Own custody features beyond the device key (second passkey and
revocation become PDS account features, kept only until the PDS path
works). The log as source of truth. Our own vouch record if Tangled's
or the certified badge fits.
